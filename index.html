Le guide HTML/CSS pour débutants

Ce guide sera ton meilleur allié en tant que débutant, pour t'accompagner dans ton apprentissage de HTML/CSS

Ce guide te présente les deux langages fondamentaux du web : HTML, qui structure le contenu d'une page, et CSS, qui en définit l'apparence. Tu trouveras ici les balises essentielles à connaitre, des exemples concrets d'utilisation, et des bonnes pratiques pour écrire un code propre et lisible dès le début. Pas besoin de prérequis, commence de zéro !

Découvrez HTML/CSS

1. Pourquoi apprendre HTML/CSS ?

HTML : la structure du site

Le HTML et le CSS sont des langages web de base ; on commence généralement par leur apprentissage car ils sont assez simples à comprendre et car ils sont incontournables.

Le HTML (HyperText Markup Language) est le langage de balisage qui donne la structure à une page web. Il indique au navigateur ce qu'est chaque élément : un titre, un paragraphe, une image, un lien. Sans HTML, il n'y a pas de page web.

  • HTML est interprété directement par le navigateur.
  • Il utilise des balises pour délimiter chaque élément.
  • Chaque balise a une signification sémantique précise.
  • Il est inséparable de CSS pour l'affichage.
  • Sa version actuelle est HTML5.
  • Toutes les recommandations officielles à respecter sont présentées dans W3School. Et il peut se valider via le W3C validator.

Exemple de code HTML :

<h1>Mon titre</h1><p>Mon paragraphe</p>

CSS : la mise en forme

CSS (Cascading Style Sheets) contrôle l'apparence visuelle des éléments HTML : couleurs, polices, marges, disposition. Sans le CSS, une page s'affiche en texte brut sans aucune mise en forme. Il définit les styles associés à un document HTML.

  • CSS se lie au HTML via une balise <link> dans le <head>
  • Les règles CSS suivent la syntaxe : sélecteur { propriété: valeur; }
  • La cascade détermine quelle règle s'applique en cas de conflit.
  • Flexbox et Grid permettent de créer des mises en page complexes.
  • Les media queries rendent le site adaptatif (responsive).
  • Les variables CSS centralisent les valeurs réutilisables.

3. Suivre une structure de base

Le fichier HTML doit toujours contenir ces élements essentiels :

  • <!DOCTYPE html>: indique que c'est un document HTML.
  • <html>: la racine de la page.
  • <head>: contient des métadonnées (titres, liens vers CSS, etc.).
  • <body>: contient tout ce qui sera visible sur la page.

4. Utiliser un navigateur pour tester

Ouvrir le fichier HTML dans un navigateur (Chrome, etc.) pour visualiser la page. On peut utiliser l'outil "DevTools" des navigateurs pour inspecter la page.

Pourquoi les apprendre ensemble ?

HTML et CSS fonctionnent en binôme : l'un sans l'autre ne suffit pas. HTML apporte le fond, CSS apporte la forme. Comprendre les deux te donne le contrôle total sur ce qu'une page affiche et comment elle le présente.

  • HTML seul donne une page fonctionnelle mais sans style.
  • CSS seul n'a aucun élément à mettre en forme.
  • La séparation fond/forme facilite la maintenance du code.
  • Un HTML sémantique rend le CSS plus facile à cibler.
  • Ensemble, ils permettent de créer des interfaces accessibles.
  • Ils sont la base avant d'aborder JavaScript.

2. Balises de base

Pour écrire en langage HTML, les balises sont indispensables. Une balise est utilisée pour créer un élement. Le nom d'un élément HTML est le nom qui apparaît au début de la balise ouvrante (<>) de l'élément et à la fin de la balise fermante de l'élément (</>) (si l'élément possède une balise de fin).

Quelques exemples de balises de base et des exemples d'utilisation
Balise A quoi elle sert ? Exemple d'utilisation
<h1> Titre principal de la page. Il y a aussi <h2>, <h3>... jusqu'à <h6> pour les sous-titres. Chaque page doit avoir exactement un <h1>. <h1>Le guide HTML</h1>
<p> Balise pour les paragraphes. Elle définit un bloc de texte. C'est la balise la plus utilisée avec <h1> pour la structure. <p>Ceci est un paragraphe.</p>
<a> Balise pour créer des liens hypertextes. L'attribut href spécifie l'URL de destination. Elle peut pointer vers une page, une section, ou un email. <a href="https://exemple.com">Lien</a>
<img> Balise pour insérer une image. Elle utilise l'attribut src pour le chemin de l'image et alt pour un texte alternatif (important pour l'accessibilité). <img src="photo.png" alt="photo">
<ul> et <li> <ul> crée une liste non ordonnée (avec puces) et <li> ajoute chaque élément. Idéal pour énumérer des éléments sans ordre. <ul><li>Élément 1</li><li>Élément 2</li></ul>
<button> Balise pour créer un bouton interactif. Elle peut être utilisée dans un formulaire (type="submit") ou simplement pour déclencher une action avec JavaScript. <button>Cliquez-moi</button>
<div> Balise conteneur générique pour grouper des éléments. Elle ne a aucune signification sémantique particulière, elle sert juste à organiser le layout avec CSS. <div><p>Contenu</p></div>
<form> Balise pour créer un formulaire. Elle contient des champs comme <input>, <textarea> et des boutons pour collecter des données utilisateur. <form><input type="text"><button>Envoyer</button></form>

3. Tips & bonnes pratiques

Quelques conseils pratiques pour un code HTML / CSS bien structuré, lisible et optimisé

Indentation et lisibilité

Indentez votre code avec 2 ou 4 espaces (ou une tabulation). Un code bien indenté est beaucoup plus facile à lire et à maintenir. Cela devient crucial quand le projet grandit ou qu'une autre personne doit comprendre votre code.

Sémantique avant tout

Utilisez les bonnes balises pour le bon contenu. Préférez <header>, <nav>, <main>, <section>, <article>, <footer> à une multitude de <div>. Cela améliore l'accessibilité et le référencement.

Nommez vos classes clairement

Les noms de classe doivent être descriptifs. Préférez "nav-principale" à "nav1" ou "menu". Évitez les abréviations confuses. Cela rend le CSS beaucoup plus facile à maintenir et à comprendre.

Commentez votre code

Ajoutez des commentaires pour expliquer vos intentions, surtout pour les parties complexes. Commentez vos sections CSS (ex: /* Header */) pour faciliter la navigation. Mais ne sur-commentez pas du code évident.

Pensez au responsive dès le départ

Utilisez Flexbox et Grid plutôt que des positions fixes. Préférez les unités relatives (em, rem, %) aux pixels fixes. Les media queries doivent adapter votre design, pas le reconstruire complètement.

Testez sur plusieurs navigateurs

Votre site doit fonctionner sur Chrome, Firefox, Safari et Edge. Utilisez DevTools (F12) pour inspecter votre code. Testez aussi sur mobile et tablette pour vérifier que le responsive fonctionne vraiment.
